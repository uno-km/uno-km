Ollama Comparison & Hardware Benchmarks

Objective architectural comparison between Ollama and Termux-BitNet on Android ARM64 hardware.

1. Architecture & Engineering Comparison Table

Evaluation Dimension Standard Ollama (via PRoot/Linux) Termux-BitNet (Native Bionic Core) Technical Ground Truth & Tradeoff
Execution Model Background HTTP Server Daemon (Go runtime + REST API) In-Process C ABI / Direct Shared Library Termux-BitNet eliminates socket serialization and background daemon memory overhead.
Android/Termux Portability Requires glibc (PRoot) or custom patched Go toolchains; high build failure rate Native Android Bionic (C++17 + libc++) Compiles and runs directly in Termux without virtualization or PRoot overhead.
Weight Representation Standard 4-bit (Q4_K_M) / 8-bit (Q8_0) Ternary 1.58-bit (i2_s: -1, 0, +1) 1.58-bit parameters reduce model size from ~4.5 GB (4-bit 7B) to ~1.13 GB (2.4B), saving RAM bandwidth.
SIMD Compute Kernel General FP16/INT8 GEMM routines ARM64 NEON DotProd (vdotq_s32) Multiplies 1-bit weights via integer dot product instructions, reducing ALU power draw.
Process Memory Footprint ~200 MB base daemon + model weight buffer Low base overhead (~15 MB C ABI) + model buffer Significantly reduces likelihood of triggering Android Low Memory Killer (LMK).
SDK Gateways REST API / Ollama-JS / Ollama-Python HTTP clients Python ctypes Zero-Copy FFI + Node.js IPC Provides direct programmatic access without open network ports.
