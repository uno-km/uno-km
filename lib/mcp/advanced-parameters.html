고급 파라미터 제어 및 런타임 튜닝

WASI 샌드박스 보안 격벽, 인메모리 퓨얼 할당 및 포트 브리지 제어 (AMEVA-MCP-Hub)

Release: v3.1.3
핵심 가치 제안 (Why It Matters)

WASI 바이트코드 실행 중 악의적인 무한 루프나 메모리 점유를 원천 차단하고, 다중 IDE 동시 연동 시 포트 충돌 없이 안정적인 도구 중계를 보장하는 런타임 파라미터 규격입니다.

1. 허브 서버 및 네트워크 브리지 제어 파라미터

파라미터명 (CLI 플래그) 기본값 / 범위 시스템 동작 및 네트워크 엔지니어링 분석
--port 11553 (1024 ~ 65535) 허브가 청취하는 TCP 포트. 이미 활성 인스턴스가 존재할 경우 자동 감지하여 브리지 모드로 전환합니다.
--bridge-mode auto (true | false) 포트 점유 시 EADDRINUSE 오류를 내는 대신 기존 프로세스에 투명하게 stdio를 포워딩하는 다중 인스턴스 공유 모드.
--headless false (IDE 연동 시 auto) 서버 기동 시 브라우저 관리자 대시보드 팝업을 차단하고 백그라운드 데몬으로 조용히 실행하는 헤드리스 플래그.
--require-token false (loopback) 로컬 루프백 인터페이스 접속 시 불필요한 보안 토큰 인증을 생략하여 IDE 연동 마찰을 제거합니다.

2. WASI 샌드박스 리소스 격벽 파라미터

파라미터명 기본값 보안 격벽 기능
fuel_limit 10,000,000 연산 WASI 바이트코드 실행 인스트럭션 한도. 계산 복잡도 폭증이나 무한 루프 감지 시 즉각 실행을 중단합니다.
max_memory_pages 256 페이지 (16 MB) WASM 선형 메모리 상한선 (64KB/페이지 단위). 호스트 프로세스의 OOM 공격을 선제 차단합니다.
timeout_ms 30,000 ms 개별 도구 호출의 최대 허용 실행 시간. 초과 시 강제 타임아웃 인터럽트를 발생시킵니다.
vector_dimensions 1536 차원 AI 임베딩 벡터 코사인 유사도 연산 및 Top-K 검색 버퍼 차원 수.
