Advanced Parameters & Tuning

LoRA tuning, CPU threading, and gradient accumulation optimization

Kernel Tuning for Constrained Edge Hardware

Fine-tune threading, memory allocation reuse, and LoRA rank parameters to maximize training throughput while staying within thermal and RAM budgets.

1. LoRA (Low-Rank Adaptation) Hyperparameters

Parameter Recommended Value Description & Trade-offs
r (LoRA Rank) 4 or 8 Dimension of the low-rank decomposition matrices \( A \) and \( B \). Rank 8 captures 95%+ adaptation capacity while adding <1% memory overhead.
lora_alpha 16.0 (typically \( 2 imes r \)) Scaling multiplier applied to low-rank delta updates: \( ext{scale} = rac{lpha}{r} \). Stabilizes learning rate dynamics.
lora_dropout 0.05 Dropout probability applied to intermediate low-rank representations during on-device training.

2. Termux CPU Threading & OpenBLAS Configuration

Set environment variables prior to Python initialization to maximize ARM64 multicore utilization without triggering thermal throttling:

# Set optimal thread pool for 8-core ARM64 processors
export OMP_NUM_THREADS=4
export OPENBLAS_NUM_THREADS=4
export MKL_NUM_THREADS=4
export VECLIB_MAXIMUM_THREADS=4

# Disable Python garbage collection pauses during tight inner step loops
export PYTHONUNBUFFERED=1

3. Gradient Accumulation & Memory Savings

Simulate large batch sizes without exceeding smartphone RAM constraints by accumulating gradients over multiple micro-steps:

# Effective Batch Size = Micro-Batch (16) * Accumulation Steps (4) = 64
accumulation_steps = 4
optimizer.zero_grad()

for i, (x_batch, y_batch) in enumerate(dataloader):
    logits = model(x_batch)
    loss = criterion(logits, y_batch) / accumulation_steps
    loss.backward()
    
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()

4. Rotary Position Embedding (RoPE) Scaling

Parameter Default Value Tuning Guidelines
base (Frequency Base) 10000.0 Base frequency constant for rotary angle computation. Increase to 500000.0 when extending context window length.
max_seq_len 512 Precomputes inverse frequency buffers up to this length to avoid dynamic sine/cosine computation during training.
