WGSL workgroup sizing, buffer quota management, and FP16 half precision

WGSL Shader & Pipeline Optimization

Fine-tune workgroup tiling dimensions, staging buffer pools, and precision modes to extract maximum FLOPS from heterogeneous client GPUs.

1. WGSL Workgroup Tiling Dimensions

Workgroup Configuration Optimal Device Class Trade-offs & Tuning Guide
@workgroup_size(16, 16) (Default) Desktop GPUs (NVIDIA / AMD) 256 threads per workgroup. Optimal register occupancy and cache reuse for tiled matrix multiplication.
@workgroup_size(8, 8) Mobile GPUs (Adreno / Mali) 64 threads per workgroup. Reduces shared memory pressure on mobile tile-based deferred renderers (TBDR).
@workgroup_size(32, 1) Apple Silicon M-Series Aligns with SIMD32 execution width for coalesced memory access on Metal unified memory architectures.

2. Buffer Pool Quota & WeakRef Lifetime Management

Configure internal buffer pool limits to avoid GPU memory exhaustion on low-spec client machines:

import { BufferPool } from 'https://uno-km.github.io/uno-km/lib/forge/dist/index.esm.js';

// Configure Maximum VRAM Pool Threshold (e.g., 256 MB)
BufferPool.setMaxPoolSize(256 * 1024 * 1024);

// Enable Immediate Garbage Collection of Unreferenced Intermediate Tensors
BufferPool.enableWeakRefGC(true);

3. Float16 (FP16) Half-Precision Acceleration

Enable native 16-bit floating point compute shaders on GPUs supporting the shader-f16 WebGPU extension:

const adapter = await navigator.gpu.requestAdapter();
const features = [];
if (adapter.features.has('shader-f16')) {
  features.push('shader-f16');
  console.log("Hardware FP16 Half-Precision Enabled: 2x Theoretical FLOPS");
}
const device = await adapter.requestDevice({ requiredFeatures: features });
